# Repository Guide

## Boundaries

- This is an F# HDL plus a Rust board runtime; there is no live Kotlin or Gradle build despite the checkout path.
- `hdl/` contains the DSL, simulator, emitters, debugger, designs, and runnable design heads. `runtime/` is a separate Rust workspace for drivers and board programs. `hardware/` consumes emitted RTL for Vivado/iCE40 flows.
- `hdl/Warp11.sln` excludes browser/WASM projects; build those explicitly when working on the site.
- F# compile order is dependency order. Treat each `.fsproj`, especially `hdl/Warp11/Warp11.fsproj`, as authoritative before moving or adding files.
- `Warp11.Design` models editable designs as data and depends on `Warp11`; the HDL library must not depend on `Warp11.Design`.

## Local Commands

The .NET 10 SDK may not be on `PATH`:

```sh
export PATH="$HOME/.dotnet:$PATH"
cd hdl
dotnet build Warp11.sln
```

`Warp11.Designs.Tests` is the first Expecto suite; run it directly so failures return a nonzero status:

```sh
cd hdl
dotnet run --project Warp11.Designs.Tests
```

Most remaining F# verification is embedded as "living checks" in executable projects. Run the owning project for focused feedback, for example:

```sh
cd hdl
dotnet run --project Warp11.Designs
dotnet run --project Warp11.Mandelbrot
dotnet run --project Warp11.Gep
dotnet run --project Warp11.Placement
dotnet run --project Warp11.Tutorial.App -- check
```

Check each executable's exit behavior before relying on it as a CI gate: some checks print Boolean results, and `census.fsx` is reporting-only.

Rust is rooted separately:

```sh
cd runtime
cargo test --workspace
```

`runtime/core` is `no_std` and dependency-free. `runtime/Cargo.lock` is ignored, so do not treat the local lockfile as a committed workspace contract.

## Generated Seams

- `runtime/core/src/*_layout.rs` is generated and committed because Rust compiles against it. Never edit these files by hand.
- A register-map change must be regenerated by its owning F# project and include the Rust layout diff. Typical commands, run from `hdl/`, are:

```sh
dotnet run -c Release --project Warp11.Mandelbrot -- hardware <repo-root>
dotnet run -c Release --project Warp11.GoL.App -- hardware <repo-root>
dotnet run -c Release --project Warp11.Gep -- hardware <repo-root>
dotnet run -c Release --project Warp11.Effects -- hardware <repo-root>
```

- These commands also populate ignored `hardware/build/`. It is build output shared by several projects, not a committed golden tree.
- Do not hand-edit generated canvas board/build directories. Generate examples with `dotnet run --project Warp11.Placement -- examples Warp11.Placement.Canvas/examples`.

## HDL Invariants

- `hdl/Directory.Build.props` makes FS0025 an error and enables FS1182. An apparently unused binding can still elaborate hardware; a leading `_` can intentionally retain that side effect. Verify emitted RTL before deleting one.
- Preserve call-site invariance: callers should not distinguish inline logic from an instantiated module.
- One driver per signal, one declaration per name, width checks, name checks, and exactly one stream consumer are elaboration invariants. Public emission goes through `emitDesign`, which enforces them.
- Do not pass remembered latency between modules. Cycle-costing components expose streams or carry caller context through themselves.
- Declare storage explicitly. A combinational read is valid only for distributed memory; block/ultra memory requires synchronous read ports.
- Project-specific unit factories must be registered before loading designs that name them. The factory registry is process-wide, not thread-local.
- For a structural refactor, compare emitted Verilog before and after, including every parameterization that changes ports. Green behavioral checks alone do not prove structural equivalence.

## Differential Oracle

Run from `hdl/`:

```sh
./run_differential.sh
FIRTOOL_LEG=1 ./run_differential.sh
```

- This is expensive because it compiles a Verilator binary per design; the firtool leg roughly doubles the work. Do not run it routinely or unprompted. Use it for emitter/IR/simulator changes, release gates, or before a bitstream.
- Require the final `ALL DIFF PASS`. An early abort prints `INCOMPLETE` and partial counts.
- Do not add `verilator -j 0`; Verilator 5.020 is documented as intermittently failing there.
- Firtool is optional and pinned by `hdl/tools/install-firtool.sh`; set `FIRTOOL_LEG=1` only when that independent leg is intended.

## Hardware Gotchas

- Before a bitstream build, ask whether the differential oracle should run. Vivado builds are long-running and require its environment to be configured.
- Run the matching `runtime/host/src/bin/*_first_light.rs` program on the board after every bitstream change. Simulation plus timing closure does not prove host-visible behavior.
- For simulation-clean corruption on hardware, inspect routed timing/WNS first; the simulators have no timing model.
- Never unload a bitstream while fabric AXI transactions are in flight. Stop and disarm Game of Life before unload; HP0 pairing skew can otherwise require a board reboot.
- `runtime/.cargo/config.toml` intentionally uses `rust-lld` and the 8-byte `runtime/musl-stub/libdl.a` for musl cross-linking. Do not remove the archive.
- Use `hardware/ice40/build.sh` for iCEBreaker work; it selects the pinned OSS CAD suite and sanitizes `LD_LIBRARY_PATH`. `iceprog -S` does not configure the tested board; use `PROG=1` and verify `cdone`.

## Site

- `site/package.json` exists to pin Wrangler; `npm test` intentionally fails and is not a repository test command.
- Site output under `site/out/` and `site/apibuild/` is ignored and may be stale across checkouts. `site/build.fsx` tolerates missing WASM/API artifacts, so its success alone does not prove a complete site.
- Deploy from `site/` using the lockfile-pinned tool: `npm install && npx wrangler deploy`. Node 20+ is required.
